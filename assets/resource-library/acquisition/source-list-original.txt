EUCLIDI GAMES — SHARED ASSET LIBRARY
Agent acquisition manifest and operating instructions
Version: 1.0 | 2026-11-27

OBJECTIVE
Build a reusable, searchable asset library for Euclidi Games and future interactive projects. Acquire actual source assets, not merely bookmarks. Prioritize coherent, high-quality, reusable collections covering 2D, pixel art, 3D, animation, materials, audio, UI, fonts, shaders and specialized simulation content. The immediate project is Harvest '96, a 16-bit rural life simulation; the library must also support unrelated future projects.

DESTINATION
Game repository: https://github.com/euclidi/euclidi-games
The agent must inspect the existing repository and asset conventions before writing. Prefer a separate shared asset repository or a dedicated shared-assets directory if appropriate; do not assume authority to create a new repository. Preserve existing games and assets. Keep raw library assets outside deployed runtime bundles where feasible. Do not import entire massive collections into the game catalog's published site indiscriminately. If storage, repository quota, or bandwidth prevents a bulk acquisition, use a versioned source manifest plus selective downloads. Do not use Git LFS without confirming that deployment and retrieval consumers support it.

LICENSE POLICY — REQUIRED
1. CC0, verified public domain, and permissive redistribution licenses are preferred. Free-to-play, free-to-download and free-for-commercial-game-use do NOT establish standalone redistribution rights.
2. Verify the original publisher's license for each pack and, when required, each file. Mirror claims are leads, not proof. Save original license and source URL alongside every acquisition. For CC BY, preserve creator, title, source, license URL, and modification notices. Keep font OFL notices, software notices and any share-alike obligations intact.
3. Never mirror assets with standalone redistribution restrictions, proprietary game rips, unverified rights, noncommercial-only terms, or ambiguous licensing into the public library. Store their source link and restriction in the manifest only. Mixamo and non-CC0 Quaternius packs are examples of sources that may permit game integration but not raw redistribution; check current terms.
4. Do not use a license label below as automatic permission; all sources are candidates and their current terms and URLs require verification. Do not bypass rate limits, logins, paywalls, or provider terms. If an official API requires permission for automated bulk access, use an authorized method or selective downloads.
5. Never execute scripts from downloaded asset packs. Inspect archives for unsafe paths, executables, duplicate content and unexpected file types. Use trusted tools to validate images, audio and model files.

ACQUISITION ORDER
P0: Bulk CC0 2D collections, Kenney, Ninja Adventure, compatible farming assets, core audio, and pixel fonts.
P1: Rigged characters, animation, modular 3D packs, environment props, textures, materials and HDRIs.
P2: Specialized assets, additional audio, UI, shader sources, scientific/historical objects and reference collections.
P3: Mixed-license directories and project-specific-only sources. Index first; acquire only individually verified eligible assets.

- Ground: grass, dirt, tilled soil, wet soil, paths, stone, water, shoreline, cliffs, fences and transitions, four seasons and weather variants.
- Flora: trees, orchard stages, flowers, bushes, weeds, mushrooms, logs, stumps, grass, reeds, crop stages and diseased/wilted/harvestable variants.
- Buildings: farmhouse, barn, coop, shops, carpentry workshop, bakery, public buildings and modular interiors.
- Characters: consistent proportions, front/back/left/right idle and walk, tool use, watering, carrying, fishing, sleeping, sitting and interaction poses. Distinct villager clothing and hair.
- Animals: cows, chickens, sheep, goats, pigs, ducks, rabbits, horse, dog, wildlife and juvenile variants; directional walk, idle, graze, sleep and relevant care animation.
- Props/items: tools, seeds, produce, feed, furniture, bedding, crates, baskets, barrels, household items, signs, mining resources, artisan production equipment.
- UI: bitmap fonts, inventory icons, dialogue boxes, calendars, journals, controller prompts and ledger widgets matching the visual era.
- Audio: footsteps by surface, doors, tool impacts, water, animals, wind, rain, ambience, interface sounds, seasonal music loops.
- Import matching assets first, not random isolated items. Assess one representative in-engine benchmark before scaling visual production. Existing Tiny Farm/Town/Dungeon imports are integration baselines, not proof of final SNES fidelity. Do not mix incompatible art styles just to maximize asset count. Do not use ripped Harvest Moon assets.

REQUIRED MACHINE-READABLE ASSET RECORD
For each pack or asset, emit a JSON record containing:
  id, title, creator, publisher, source_url, download_url (if verified), license_id, license_url, license_evidence_path, redistribution_allowed, attribution_text, local_path, sha256, bytes, format, categories, tags, style, dimensions_or_scale, animation_names, dependencies, original_or_derived, source_asset_id (for derived files), acquisition_date, verification_status.
Use null for unknown fields, not invented values. Include optional pixel cell size, sprite frame map, rig/skeleton name, axis/units, triangle count, texture resolution, audio duration, channel count, and loop markers when available. Keep manifest version and source retrieval date. Record blocked sources with specific reason, including not-found, terms, rate limit, license ambiguity or file size.

QUALITY AND RUNTIME VALIDATION
- 2D: decode PNGs, check alpha, actual cell size, atlas margin/spacing, frame bounds, direction naming and animation counts. Do not infer frame semantics without visual inspection.
- 3D: validate glTF/GLB, meshes, transforms, units, skeletons, animations and all texture references. Preserve originals; produce lower-poly/texture-size variants as needed without claiming equivalence.
- Audio: verify decoding, duration, channels, loops and suitable compression. Keep original lossless data where reasonable.
- Fonts: verify glyph coverage, font license, browser format and required attribution.
- Shaders: verify syntax, target engine/backend and license; do not assume Godot or Libretro shaders run directly in Phaser/WebGL.
- For browser projects, favor static-relative URLs, local runtime dependencies and optimized per-game bundles. Validate actual GitHub Pages deployment with no broken asset routes. Do not publish the entire raw asset collection as a game download.

EXECUTION AND REPORTING
Inspect repo state and existing asset storage; deduplicate. Process P0 through P3 in sensible batches, checkpointing each verified batch. Use official archives/releases/APIs when available. Commit assets plus manifests and license notices atomically; avoid overwriting concurrent changes. Preserve existing branches, game builds and catalog. Use a development branch for large imports. Only merge when validation passes and the intended destination is confirmed.
Report actual downloaded pack/file counts, bytes, licenses verified, assets rejected, duplicates skipped, checks passed/failed, commit/PR links and remaining coverage gaps. Distinguish discovered links, acquired assets, integrated assets and tested assets. Do not claim a pack was imported solely because its page was found. Do not present a Play button until the specific game route and catalog entry are actually verified. Continue across available batches without asking for approval for every ordinary download; request authorization only for consequential repository/storage changes, uncertain redistribution rights, or required access.
