EUCLIDI GAMES | BILLIARDS FREE ASSET ACQUISITION MANIFEST
Revision: 2026-11-27 | Format: agent-readable UTF-8 plain text
Target: reusable browser-game asset repository, not a single disposable demo.

PURPOSE
Acquire a coherent, reusable collection for realistic 3D pool, 2D/retro pool,
8-ball, 9-ball, 10-ball, blackball, snooker, carom, training and optional pool-hall
expansion. No engine or visual style is approved by this manifest. Do not treat
this file as an instruction to build or deploy a game.

STATUS AND LICENSE KEY
P0 = acquire first; P1 = acquire for visual/audio polish; P2 = optional expansion.
CC0 = preferred for a public shared asset library. CC BY = attribution required;
retain the exact license version, author, source and modification record.
REVIEW = candidate only; verify actual file license, provenance and download
terms before fetching. REF = reference or software, not a redistributable art
asset by default. GPL = keep separate; do not incorporate without a compatible
licensing decision. Free download is not proof of permission to redistribute.
The URLs below are source/download pages, not guessed binary endpoints. Source
listings were researched on the stated date; archives, model quality, individual
files and runtime compatibility have not been downloaded or tested. Library and
software links marked REVIEW/REF need further verification. No assets have been
copied into the Euclidi Games repository by this task. This is a practical broad
inventory, not a claim to enumerate every free asset on the internet.

10 | AGENT ACQUISITION AND INTEGRATION CONTRACT
======================================================================
1. Inspect the existing Euclidi Games asset folder before downloading. Deduplicate
   by source URL, source ID and SHA-256. Reuse compatible existing assets first.
2. Read source page and archive license. Capture source URL, author, license
   version, access date, filename and required attribution. If terms are missing
   or conflict, quarantine metadata only. Do not bypass logins or paywalls.
3. Fetch P0 art and audio in priority order. Use source pages or official APIs,
   avoid blind recursive mirrors and third-party download wrappers. Respect API
   limits, site terms and practical storage limits. Preserve source files only
   where redistribution is explicitly allowed. Where it is not, keep links only.
4. Open representative models and sounds before bulk import. Record dimensions,
   material maps, mesh count, UVs, topology, rig, format and quality issues.
   Compare equipment variants visually and select a coherent family. Do not
   equate free or high polygon count with quality. Obtain visual benchmark
   approval before mass custom asset generation or expanding a generated set.
5. Normalize to meters (SI internally), consistent axes, correct pivots and scale.
   GLB/glTF 2.0 for browser 3D; PNG for pixel assets and alpha; WebP/KTX2 for
   suitable runtime textures; WAV master, Ogg/MP3 runtime audio; WOFF2 fonts.
   Preserve per-source licenses on converted files. Only use compression that the
   actual selected runtime and target browsers support.
6. Retain proper UV-mapped stripes and numbers attached to ball rotations.
   For a missing ball marking or exact collision sphere, procedural generation
   is justified by geometry/physics requirements. Do not substitute basic shapes
   for complex table furniture, cushions, pockets, cues or player models.
7. Build a coverage ledger: REQUIRED / AVAILABLE / IMPORTED / TESTED / MISSING.
   Do not mark assets tested from a search result. Test with actual scene
   lighting, runtime importer and touch/desktop camera distances.
8. Add P1 assets selectively and P2 only where planned scope needs them.
   Keep original sources separate from optimized runtime assets. Do not place
   all high-resolution source archives in the public Pages build. Record size
   budgets; avoid unnecessary Git history growth and duplicated variants.
9. Generate credits and a machine-readable inventory. For CC BY, record creator,
   title if supplied, source, license URL and indication of changes; preserve
   other required notices. For CC0, keep provenance even though attribution
   is generally not required. Keep code licenses separate from art licenses.
10. Verify catalog entries and deploy only when the actual approved game is
    implemented and tested; the asset manifest itself authorizes no deployment.

11 | COVERAGE GAPS TO RESOLVE BEFORE CLAIMING ASSET COMPLETENESS
======================================================================
- Confirm complete, correctly numbered 1-15 ball set, cue ball markings and
  accurate snooker/carom/blackball variants. BIL-001 is the first candidate,
  but actual textures have not been inspected.
- Validate authentic table construction, dimensions, cushion profile, pocket
  jaws, slate bed, ball return, and correct independent geometry. Existing
  free meshes may only be decorative and need substantial adaptation.
- Find/derive a complete chalk, brush, cue tip, cue case and rack accessory set.
- Find authentic isolated rail rebounds, felt rolling and chalking recordings;
  the cited audio candidates have not been auditioned.
- Find a consistent, rigged pool-player character and billiards-specific motion
  set if visible players are required. No verified dedicated motion pack found.
- Build/select coherent room environment if walkable venues are required;
  an HDRI alone does not satisfy a 3D room requirement.
- Produce original unbranded signs, scoreboards, diagrams, number atlases and
  functional interface art where source candidates do not meet the style.
- Verify licenses and provenance for the exact files downloaded; newer source
  claims are not independently validated. Reject any file with unclear rights.
