PURPOSE
Build an expandable, legally redistributable, reusable source-asset library for
Kinetic∆ and future Euclidi Games projects. This is an acquisition queue, not a
claim that the assets have been downloaded, inspected or imported. A finite
manifest cannot cover every possible future project; use the discovery sources
and coverage matrix below to extend it without duplicating assets.

AGENT EXECUTION CONTRACT
1. Resolve each source page to the original free archive, official release or
   asset file. A product page is not a direct download URL. Never guess URLs,
   scrape protected downloads, bypass logins or purchase a paid edition.
2. Verify the exact edition, author, license and right to redistribute original
   files publicly on GitHub. FREE TO USE IN A GAME is not the same as permission
   to mirror a source library. CC0 is preferred. CC BY needs attribution and
   change notices; OFL fonts need their license and reserved-name compliance.
   MIT/Apache/BSD/ISC code licenses are not blanket licenses for bundled artwork.
   Reject NC, ND, editorial-only, unclear provenance, ripped game assets,
   assets using protected brands/characters, and unauthorized reuploads.
   Do not mirror assets with a game-use-only or no-standalone-redistribution
   license. CC BY-SA/GPL art and code require explicit compatibility review.
3. Archive exact original license text and source-page URL; record download URL,
   date, version, author, attribution, redistribution permission and SHA-256.
   If source terms conflict, pause that entry and mark LICENSE_REVIEW.
4. Prefer existing asset families; add new families only to fill a specific gap
   or enable a genuinely different visual direction. Preserve independent art
   grammars. Never combine 2D pixel scales or 3D rigs without validation.
5. Before committing, validate safe archive paths, CRC/hash, MIME, file sizes,
   dependencies, GLTF buffer/texture URIs, image transparency, audio loops,
   model bounds/pivot/scale/axis, skeleton/clips and actual import in target engine.
   No executable installers, macros, arbitrary scripts or nested archive bombs.
6. Store original packs (where legally permitted) with licenses. Extract only
   game-ready curated subsets; don't retain multiple full copies. Keep source
   and runtime versions distinct. GLB preferred; retain original FBX/Blend only
   where useful. Audio: source WAV, optimized OGG/Opus where supported. Textures:
   1K default, 2K only when justified; use KTX2/Basis or WebP for runtime as useful.
7. Public GitHub repository: do not indiscriminately clone every asset catalog.
   Check GitHub limits and Pages deployment size before adding files. Keep raw
   large source archives in a separate authorized asset store or manifest-only
   queue if necessary; no single ordinary Git blob >=100 MiB. Do not place
   Git LFS pointers in live runtime routes. Exclude raw archives, source files,
   previews and acquisition scripts from deployed Pages artifact. Package only
   used, optimized game assets. Do not reconfigure unrelated games or workflows.
8. Use sequential small batches by asset family. Validate one representative
   model/rig/texture combination before expanding. Respect the owner's visual
   benchmark approval rule for newly generated asset families; downloading an
   existing pack does not imply final art direction approval.
9. Update library indexes, SHA256SUMS.txt, source-record.json and project credits.
   Commit in a dedicated branch. Do not publish unfinished game or catalog art.
10. Status per entry: QUEUED / DOWNLOADED / LICENSE_VERIFIED / IMPORT_VERIFIED /
    VISUAL_REVIEW / INTEGRATED / BLOCKED / DUPLICATE. Never conflate these.
